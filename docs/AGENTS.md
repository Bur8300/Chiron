# Documentation rules

Read the root `AGENTS.md` first.
Write in Simplified Technical English: short sentences, active voice and consistent terms.
Preserve the T, D, WBS, FR, NFR and UC identifiers in the project documents.

## Locations

- Keep course reports directly in `docs/` with the filenames in the root rules.
- Keep interface and architecture notes in `docs/design/`.
- Keep validation evidence in `docs/testing/`.
- Put wireframe exports in `docs/design/wireframes/` and explain navigation in its README.
- Clearly distinguish proposed wireframes, screenshots of implemented pages and final acceptance results.

## Course submissions

Use the prescribed `docs/<document>` branch, filename and release name from the course guide.
A release from the document PR branch is the submitted version. A PR alone is not a submission.
Obtain teammate approval before requesting TA review.
Fix TA comments in the same PR. Do not delete or recreate a published release.
The AI agent does not merge PRs or create releases.

## Evidence

State the owner, activity, sources, draft status, dependencies and limits of each design or validation note.
Link requirements to implementation and tests where possible.
Do not claim an AI draft has received human review, a grade, a usability score or test results that are not recorded.
Mark missing contract integration and other incomplete work explicitly.
Do not change a deadline silently when the issue, chat plan and course announcement differ.
